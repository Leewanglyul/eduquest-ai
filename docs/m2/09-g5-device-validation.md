## 1. PC 준비

한 번만 하면 됩니다. 명령은 `C:\Users\chamw\eduquest-ai`에서 실행합니다.

1. **로컬 DB 켜기.** Docker Desktop을 켜고, 꺼져 있으면 `pnpm db:start`. (이미 켜져 있으면 생략)
2. **로컬 프로필로 전환.**
   ```bash
   pnpm env:local
   ```
3. **시험 데이터 만들기** (학급 1개, 학생 계정 2개, 퍼즐 3개: 쉬움·보통·어려움). 다시 실행하면 이전 시험 데이터를 지우고 새로 만듭니다.
   ```bash
   pnpm dev:seed-play
   ```
   결과는 `.dev-play-seed.json`에 있습니다(정답과 시험 비밀번호가 들어 있어 git에는 올라가지 않습니다). 보기 쉽게 출력하려면:
   ```bash
   node -e "const o=JSON.parse(require('fs').readFileSync('.dev-play-seed.json','utf8'));console.log(o.accounts.map(a=>a.username+' / '+a.password).join('\n'));for(const p of o.puzzles){console.log('\n'+p.level,p.path,p.grid);console.log(p.words.map(w=>w.number+(w.direction==='across'?'가로':'세로')+' '+w.answer+' ('+w.at+')').join('\n'))}"
   ```
4. **서버 켜기** (실제 배포와 가까운 production 빌드로 시험합니다. 개발 서버는 느리고 오버레이가 끼어듭니다).
   ```bash
   pnpm build
   ```
   ```bash
   pnpm exec next start -H 0.0.0.0 -p 3000
   ```
   `-H 0.0.0.0`이 있어야 같은 Wi-Fi의 폰·태블릿이 접속할 수 있습니다. 첫 실행 때 Windows 방화벽이 Node.js 허용을 물으면 **개인 네트워크**를 허용하세요.
5. **PC의 IP 확인.**
   ```bash
   ipconfig
   ```
   Wi-Fi 어댑터의 IPv4 주소(예: `192.168.0.96`)를 씁니다. 가상 어댑터(Docker, WSL, VMware)의 주소가 아닙니다.
6. **기기에서 접속:** `http://<PC IP>:3000/student/sign-in`. 폰과 PC가 **같은 Wi-Fi**여야 하고, 학교 Wi-Fi처럼 기기끼리 막는 곳이면 폰 핫스팟에 PC를 붙이세요.
7. 로그인 후 주소창에 퍼즐 경로를 붙여 엽니다: `http://<PC IP>:3000/student/crosswords/<assignmentId>?imetrace=1`.
   (`?imetrace=1`을 붙이면 맨 아래에 **IME 기록** 칸이 나타납니다. §5)

**처음부터 다시 풀기(시도 지우기)** 는 로컬 DB에서만:
```bash
docker exec supabase_db_eduquest-ai psql -U postgres -c "delete from public.crossword_attempts"
```

**끝낼 때:** 서버 창에서 `Ctrl+C`, 그리고
```bash
pnpm env:hosted
```
로컬 시험 데이터는 로컬 DB에만 있고, `pnpm db:reset`으로 지워집니다.

> **2026-10-18 화면이 바뀌었습니다.** 이제 학생 홈에 "풀 수 있는 퍼즐" 링크, 퍼즐 목록(`/student/crosswords`), 결과 화면이 있습니다. 퍼즐을 풀면 완성 문구가 나온 뒤 결과 화면으로 넘어가고, 거기서 "다음 퍼즐 풀기"로 이어집니다. 입력창과 낱말 입력은 가로 화면(태블릿)에서는 격자 오른쪽에 있고, 세로 화면에서는 격자 아래에 있습니다. 이 기능은 **로컬 DB를 쓰는 동안만 자동으로 켜집니다** (호스팅 프로젝트에서는 `CROSSWORD_PLAY_ENABLED=true`를 직접 설정하기 전까지 꺼져 있고, 켜기 전에는 거버넌스 문서 14 승인이 필요합니다).

## 2. 시험 데이터

| 쓰임 | 퍼즐 | 이유 |
|---|---|---|
| IME 항목(§4 A, B, C) | **보통** (12낱말 안팎) | 2칸·3칸·4칸 낱말이 있습니다. 낱말 길이는 단서 줄 끝의 `(n)`에 나옵니다. 시험 데이터를 만들 때마다 낱말 배치와 번호가 달라지니, 출력의 낱말 목록에서 4칸·3칸 낱말을 찾아 쓰세요 |
| 끝까지 풀기·제출 | **쉬움** (5×5, 7낱말) | 작아서 정답(`.dev-play-seed.json`)을 입력해 완성하기 쉽습니다 |
| 제출 쿨다운 | **어려움** | 틀리게 제출하면 바로 30초 대기가 걸립니다 |

계정은 2개입니다. 기기 A에서 1번, 기기 B에서 같은 1번 계정으로 "이어서 풀기"를 시험하고, 2번은 다른 사람이 동시에 들어오는 경우용입니다. 비밀번호는 모두 `Dev#play1234`입니다.

낱말 고르는 법: 칸을 누르면 그 칸을 지나는 낱말이 선택됩니다. 가로·세로가 만나는 칸을 한 번 더 누르면 방향이 바뀝니다. 하드웨어 키보드가 있으면 Tab / Shift+Tab으로 다음·이전 단서로 갑니다. 화면의 **점선 칸**이 글자를 받는 입력창입니다(칸을 누르면 키보드가 올라와야 합니다. 안 올라오면 점선 칸을 한 번 눌러 보고, 그 사실을 기록하세요).

화면 읽는 법: 입력 중(조합 중)인 글자는 **밑줄 + 노란 칸**, 확정된 글자는 그냥 글자, 알려 준 칸은 회색입니다. 위쪽 한 줄이 저장 상태입니다.

## 4. 점검 항목

모든 항목은 **보통 퍼즐**에서 하고(별도 표기 제외), 내용이 정답이 아니어도 됩니다(칸에 그냥 글자가 들어가는지를 봅니다). 이상하면 **바로 §5의 기록을 내려받고** 메모하세요.

### A. 한글 입력 (SC1, SC2, SC3, SC5)

| # | 어떻게 | 기대 |
|---|---|---|
| A1 | 2칸 낱말 첫 칸을 누르고 `사`를 쓴다(ㅅ ㅏ) | 조합 중에는 밑줄 글자로 보이고 **입력 위치가 안 움직인다**. 다음 글자를 시작하거나 다른 곳을 누르면 확정된다 |
| A2 | 같은 낱말에 `사과`를 연달아 | `사`, `과`가 각각 **한 번씩만** 칸에 들어간다 |
| A3 | 2칸 낱말에서 `아나`를 쓴다(ㅇ ㅏ ㄴ ㅏ) | `안`의 ㄴ이 다음 글자로 넘어가 `아`, `나`가 된다. 중간에 `아아`·`안나` 같은 이상한 모양이 **남지 않는다** |
| A4 | 3칸 낱말에서 `닭고기` | 3칸에 `닭`, `고`, `기`. 마지막 글자가 틀리게 보였다가 고쳐지는 일이 없다 |
| A5 | 4칸 낱말에서 `대한민국`을 **가능한 한 빠르게** | 빠지거나 겹치는 글자가 없다. 느려서 따라오지 못하면 그것도 기록 |
| A6 | 낱말 길이보다 길게 쓴다(2칸에 `사과나무`) | 칸이 끝나면 나머지는 들어가지 않고, 다른 낱말로 넘쳐 들어가지 않는다 |
| A7 | 쓰기만 하고 **스페이스를 누르지 않은 채** 마지막 글자를 둔다 | 마지막 글자는 다음 동작(칸 누르기·다른 버튼·다른 앱)에서 한 번 확정된다 |

### B. Backspace (SC4)

| # | 어떻게 | 기대 |
|---|---|---|
| B1 | 1칸짜리 자리에서 `산`을 쓰고(ㅅ ㅏ ㄴ) **Backspace 2번** → `ㅏ` | 화면 조합 글자가 `산 → 사 → ㅅ`으로 줄고, 이어서 `ㅏ`를 치면 `사`. **칸이 지워지거나 입력 위치가 움직이지 않는다** |
| B2 | `사과`를 쓴 뒤 두 칸이 모두 빌 때까지 Backspace | 마지막 글자는 자모 단위로 지워질 수 있다(정상). 다음엔 확정된 칸이 뒤에서부터 지워지고, 앞 칸으로 입력 위치가 돌아간다 |
| B3 | 지운 뒤 `나`를 쓴다 | 첫 칸에 `나` |

### C. 칸 이동·화면 (SC3)

| # | 어떻게 | 기대 |
|---|---|---|
| C1 | `가`를 쓰는 **중에**(밑줄 상태) 다른 칸을 누른다 | `가`가 원래 칸에 확정되고 그다음 선택이 옮겨진다. **글자가 사라지거나 두 번 들어가지 않는다** |
| C2 | 조합 중에 화면을 **가로↔세로로 돌린다**(폰·태블릿) | 글자가 사라지거나 겹치지 않고, 키보드가 닫혔다 열려도 이어서 쓸 수 있다 |
| C3 | 조합 중에 홈 버튼으로 **다른 앱**으로 갔다가 돌아온다 | 쓰던 글자는 한 번만 들어 있다(없어지거나 두 번이 아니다). 저장 상태가 정상으로 돌아온다 |
| C4 | 키보드의 **추천 단어 줄**을 켜고 `사과`를 쓰다가 추천을 누른다. 한 번 끄고도 해 본다 | 추천을 누르면 그 낱말이 칸에 한 번 들어간다. 겹치거나 빠지지 않는다 |
| C5 | 복사한 `사과나무`를 점선 입력창에 **붙여넣기** (3칸 낱말) | 3칸에 `사과나`만 들어간다 |
| C6 | 키보드가 올라온 상태에서 선택한 칸과 단서가 가려지는지 | 키보드에 가려져 못 쓰는 일이 없다(스크롤로 보이면 괜찮고, 막히면 기록) |
| C7 | **낱말로 입력** 칸에 `민주주의`를 쓰고 `넣기` | 선택한 낱말 칸에 들어가고 저장된다. 격자 입력이 안 되는 기기에서는 이 방법이 대안이 된다 |

### D. 하드웨어 키보드 (Tab S9, Windows)

| # | 어떻게 | 기대 |
|---|---|---|
| D1 | 화살표 ← →, Backspace, Tab, Shift+Tab | 칸 이동, 지우기, 다음·이전 단서. **조합 중에는 움직이지 않는다** |
| D2 | 한/영 전환 후 영문 `a`를 쳐 본다 | 대문자 `A`가 칸에 들어간다(규칙상 영문·숫자도 한 글자로 허용). 확인하면 틀린 칸으로 나온다. 한글 자모만 남은 글자(ㅅ)는 들어가지 않고 "글자를 완성해 주세요."가 나온다 |

### E. 저장 상태 (PM SP-3) · 이어서 풀기

| # | 어떻게 | 기대 |
|---|---|---|
| E1 | 글자를 쓴다 | 맨 위 줄이 **저장 중 → 약 2초 뒤 저장됨** |
| E2 | **비행기 모드**(또는 Wi-Fi 끄기)를 켜고 글자를 쓴다 | 몇 초 안에 **"오프라인 · 아직 저장되지 않았어요"** 와 도움말이 나온다. 글자는 화면에 그대로 있다 |

| E6 | 오프라인 중에 탭을 닫으려 한다 | 브라우저가 "저장되지 않은 변경" 경고를 낸다 |

### F. 도구 (쉬움 퍼즐은 칸 확인 · 전체 확인도 있음)

| # | 어떻게 | 기대 |
|---|---|---|
| F1 | **낱말 확인**(보통: 남은 5번) | "다시 볼 칸이 n개 있어요" 또는 맞다는 문구, 칸에 ✓/✗. 남은 횟수가 줄어든다. 정답 글자는 나오지 않는다 |
| F2 | **글자 알려주기**(보통 2번, 확인창이 뜬다) | 선택한 칸에 글자 하나가 회색으로 들어가고 남은 횟수가 준다. 그 칸은 더 못 고친다 |
| F3 | **초성 보기** | 낱말 옆에 `ㅅㄱ` 같은 초성만 나온다 |

| F5 | **쉬움** 퍼즐을 정답으로 끝까지 채우고 제출 | "퍼즐을 완성했어요!" 후 더는 고칠 수 없다 |
| F6 | **어려움** 퍼즐에 일부러 틀리게 채우고 제출을 두 번 | 처음엔 "아직 틀린 칸이 있어요", 곧바로 다시 하면 "…초 뒤에 다시 제출할 수 있어요" |

## 5. 증거: IME 기록

실패하거나 이상하면 말로만 적지 말고 기록을 남겨 주세요. 그래야 같은 실패를 테스트로 재현할 수 있습니다.

1. 주소 끝에 `?imetrace=1`을 붙여 엽니다.
2. 화면 맨 아래 **IME 기록** 칸에 기기·브라우저(예: `Tab S9 / Chrome`), 키보드 앱, 추천 단어 줄 켬/끔, 메모를 적습니다.
3. 점검을 한 뒤 **기록 내려받기 (JSON)**. 파일이 그 기기의 다운로드 폴더에 저장됩니다. 어디로도 전송되지 않습니다.
4. 파일을 PC로 옮겨 `tests/fixtures/ime/incoming/` 에 두고 알려 주세요. 제가 컨트롤러로 다시 돌려 원인을 찾고, 같은 입력이 테스트로 남게 합니다.

기록에는 입력한 글자가 들어 있으니 시험 계정에서만 쓰세요. 기록은 새로고침하면 사라집니다. **세션 하나가 끝나면 내려받으세요.**

## 7. 문제 생길 때

| 증상 | 확인 |
|---|---|
| 폰에서 접속이 안 됨 | 같은 Wi-Fi인지, `ipconfig`의 주소가 맞는지, 방화벽(개인 네트워크 허용), 서버를 `-H 0.0.0.0`으로 켰는지. 학교 Wi-Fi는 기기끼리 막을 수 있으니 핫스팟 |
| 로그인 후 "찾을 수 없는 퍼즐" | 시험 데이터를 다시 만들면 주소(assignmentId)가 바뀝니다. 새 출력의 주소를 쓰세요 |
| 저장 줄에 "저장할 수 없어요. 다시 로그인해 주세요" | 세션이 끝났습니다. 다시 로그인 |
| 저장 줄에 "수업에서 닫힌 퍼즐입니다" | 시험 데이터를 만든 뒤 배정이 닫혔습니다(쓸 수 없는 정상 동작). 시험 데이터를 다시 만드세요 |
| 개발 중에 코드를 고쳤는데 반영이 안 됨 | `pnpm build` 후 서버를 다시 켜야 합니다(production 서버) |

알려진 한계: 이 문서의 시험은 사람이 하는 시험이라 자동으로 되풀이되지 않습니다(브라우저 자동 시험 기반은 아직 없습니다. 08의 E.7). 영문·숫자 칸과 화면 낭독기는 이 시험 범위 밖입니다.

## 9. 호스팅 수용 점검 (Hosted Acceptance)

Status: **초안, 2026-10-20. 아직 실행하지 않았습니다.** PM이 정한 최종 수용 환경은 호스팅 배포입니다(LAN 아님). §1~§7의 점검 항목(A~G)은 그대로 쓰고, 이 절은 **호스팅에서 달라지는 준비, 추가 점검, 정리, 합격 기준**만 적습니다. 문서 표기: `pilot/12`·`pilot/13` 은 거버넌스 정책과 서명, `m2/11` 은 출시 준비 감사입니다.

### 9.1 시작 조건 (모두 충족되기 전에는 시작하지 않음)

| # | 조건 | 확인 |
|---|---|---|
| 1 | **F-1이 구현되어 배포됨** ([m2/12](12-f1-feature-flag-api-gating-design.md)): 플래그가 꺼져 있을 때 6개 API가 404이고 시도 행이 생기지 않음을 호스팅에서 확인 | [ ] |
| 2 | PM이 **`CROSSWORD_PLAY_ENABLED`를 점검 기간 동안만 켜는 것**을 승인함 (켠 시각과 끈 시각을 기록) | [ ] |
| 3 | `pilot/12` 개정과 `pilot/13` 재서명 상태를 PM이 확인함. 이 점검은 **시험 계정만** 쓰므로 실제 학생 사용은 아님 | [ ] |
| 4 | F-1 전에는 호스팅에서 퍼즐을 게시하지 않는다는 운영 규칙을 지켰음 ([m2/11](11-student-play-release-readiness-audit.md) §12.1) | [ ] |

TalkBack 점검은 별도 세션입니다(`m2/11` C-2). 교사 가시성(TV-1)은 이 점검의 전제가 아닙니다.

### 9.2 격리 원칙

- 호스팅에는 **실제 파일럿 교실과 학생 62명**이 있습니다(2026-10-19 기준). 점검은 **별도 시험 교실**과 **시험 학생**으로만 합니다. 이름과 학번에 `SMOKE`를 붙입니다(예: 교실 `SMOKE 교실`, 학번 `SMOKE1`, `SMOKE2`).
- 시험 퍼즐은 **시험 교실에만** 배정합니다. 실제 교실에 배정하지 않습니다. 학생은 자기 교실에 배정된 퍼즐만 보므로 실제 학생에게는 보이지 않습니다.
- 호스팅에서는 `pnpm env:local`, `pnpm dev:seed-play`, `supabase db reset`, 시드 파일을 **쓰지 않습니다**(로컬 전용 도구입니다). 시험 데이터는 교사 화면과 정식 계정 생성 경로로 만듭니다.
- 시험 계정의 임시 비밀번호는 이 문서나 저장소에 적지 않습니다.

### 9.3 준비

1. 교사 시험 계정(또는 점검 담당 교사)으로 로그인해 시험 교실을 만듭니다.
2. 시험 학생 2명(`SMOKE1`, `SMOKE2`)을 정식 경로로 만들고 시험 교실에 등록합니다.
3. 낱말 세트를 올리고(보통 난이도, 2·3·4칸 낱말 포함, §2 참고) 퍼즐을 생성한 뒤 **시험 교실에만** 게시합니다. 쉬움·어려움 퍼즐은 §4 F항 점검에 필요할 때만 추가합니다.
4. 플래그를 켭니다(§9.1의 승인 후). 켠 시각을 기록합니다.
5. 점검 주소는 호스팅 배포 주소(HTTPS)입니다. `http://<PC IP>:3000` 같은 LAN 주소는 쓰지 않습니다.

### 9.4 점검 항목

§4의 A~F를 **Galaxy Tab + Chrome**(1순위, 최종 결정 기준)에서 호스팅 주소로 같은 방식으로 돌립니다. 세로·가로 둘 다. 그다음 Galaxy Tab + Samsung Internet(보조), Windows Chrome·Edge(선택). 호스팅에서는 다음이 **추가**됩니다.

| # | 어떻게 | 기대 |
|---|---|---|
| H1 | 시험 학생으로 **처음 로그인** (임시 비밀번호). 최초 로그인 비밀번호 변경 화면이 나온다 | 변경 전에는 퍼즐 목록과 API가 막혀 있고, 변경 후 학생 홈에 "풀 수 있는 퍼즐"이 보인다 (로컬 시드는 이 단계를 건너뛰므로 호스팅에서만 확인 가능) |
| H2 | **HTTPS**에서 로그인 유지, 새로고침, 앱 전환 후 복귀 | 로그아웃되지 않고 저장 상태가 정상으로 돌아온다 |
| H3 | **학교 Wi-Fi**(또는 실제 수업 네트워크)에서 §4 E항(저장, 오프라인, 복귀, 새로고침, 다른 기기 이어서) | E1~E6 기대와 같음. 저장 상태가 "저장 중"에 오래 머물면 지연으로 기록 |
| H4 | **같은 반 시험 기기 2~3대**가 동시에 접속해 쓰고 저장 | 저장 실패나 심한 지연이 없다. 있으면 기기 수와 시각을 기록 |
| H5 | 한 세션을 **오래 두었다가**(예: 1시간 이상) 이어서 쓴다 | 세션이 갱신되거나, 끊기면 "다시 로그인해 주세요"가 나오고 쓴 글자는 로그인 후 그대로 돌아온다 |
| H6 | 플래그가 켜진 상태에서 **시험 교실 밖의 접근**: 시험 학생이 다른 교실의 퍼즐 주소를 직접 연다 | "찾을 수 없는 퍼즐"과 같은 화면 (권한 점검) |

### 9.5 증거

- §5의 IME 기록(`?imetrace=1`)을 같은 방식으로 내려받습니다. 기록에는 입력한 글자가 들어 있으므로 **시험 계정에서만** 만들고, 저장소의 `tests/fixtures/ime/incoming/`에 둔 뒤 점검이 끝나면 정리 대상 여부를 PM과 정합니다.
- 결과는 §6 기록표에 적되 **"환경" 열에 `호스팅`** 이라고 씁니다. 호스팅에서만 생기는 문제(네트워크, 로그인, 지연)는 입력 문제(SC1~SC5)와 **따로** 적습니다.

### 9.6 점검 후 확인 (읽기 전용)

시험이 끝난 직후, 정리 전에 시험 데이터만 센다. 아래 질의는 읽기만 합니다.

```sql
select
  (select count(*) from public.students where student_no like 'SMOKE%')                       as test_students,
  (select count(*) from public.crossword_attempts a
     join public.crossword_assignments x on x.id = a.assignment_id
     join public.classrooms c on c.id = x.classroom_id where c.name like 'SMOKE%')              as test_attempts,
  (select count(*) from public.students)                                                        as all_students;
```

`all_students`는 점검 전의 값(62 + 시험 학생)과 비교합니다. 시험 교실 밖에 시도가 있으면 즉시 중단하고 PM에게 보고합니다.

### 9.7 정리

1. 플래그를 **다시 끕니다**(미설정). 끈 시각을 기록합니다.
2. 시험 학생을 계정 삭제 경로(`auth.admin.deleteUser`)로 지웁니다. 시도, 멤버, 이벤트는 함께 지워집니다 (2026-10-20 호스팅 삭제 시험으로 확인된 동작).
3. 시험 퍼즐, 낱말 세트, 시험 교실을 지웁니다.
4. 다음을 확인합니다: `SMOKE%` 학생 0, `SMOKE%` 교실 0, 시도 0, 전체 학생 수가 62로 돌아옴, 플래그가 꺼져 있음.
5. 내려받은 IME 기록 파일을 기기에서 지웁니다.

### 9.8 합격 기준과 결정

- **최종 결정(SC6)의 기준은 호스팅에서의 Galaxy Tab + Chrome** 입니다(PM, 2026-10-18). SC1~SC5가 어긋나지 않고 SC6 총평이 "예"이면 격자 입력(방식 A) 유지, 낱말 입력은 보조입니다. 실패하면 §6의 규칙대로 낱말 입력을 기본으로 합니다.
- Samsung Internet만 실패한 것은 기록하고 PM과 다시 정합니다(보조 브라우저).
- H1~H6의 실패는 입력 방식 결정과 **별개**로 출시 전에 해결할 항목입니다(로그인, 저장, 네트워크).
- 점검 절차 자체가 실제 학생 데이터를 건드리면(§9.6의 중단 조건) 점검 실패가 아니라 **절차 위반**으로 기록합니다.
